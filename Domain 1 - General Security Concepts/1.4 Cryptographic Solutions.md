## 1.4 Cryptographic Solutions

Cryptographic solutions are used to protect information and support security objectives such as confidentiality, integrity, authentication and non-repudiation.

### Public Key Infrastructure (PKI)

PKI provides a framework for managing cryptographic keys and digital certificates.

Key components include:

* **Certificate Authority (CA)** — issues digital certificates and manages certificate policies.
* **Certificate Revocation List (CRL)** — contains certificates that have been revoked.
* **Online Certificate Status Protocol (OCSP)** — allows the status of an individual certificate to be checked without downloading an entire CRL.
* **Certificate Signing Request (CSR)** — contains identifying information and a public key and is submitted to a CA when requesting a certificate.
* **Certificate Chain** — establishes trust between an end entity certificate, an issuing CA and a root CA.
* **Root of Trust** — the trusted foundation from which the certificate chain is derived.
* **Key Escrow** — allows organisations to recover cryptographic keys if they are lost.

A **root CA** is generally kept offline and only brought online for specific operations such as certificate issuance or renewal.

### Digital Certificates

Digital certificates are used to establish trust and associate identities with public keys.

Common certificate types include:

* **User certificates** — represent a user's digital identity.
* **Machine certificates** — identify computers within a domain.
* **Wildcard certificates** — support multiple hosts within the same domain.
* **Code-signing certificates** — allow software publishers to digitally sign code.
* **Email certificates** — support email signing and encryption.
* **Self-signed certificates** — issued by the same entity that uses them and generally used for internal purposes.
* **Third-party certificates** — issued by widely trusted external CAs for public-facing services.
* **Subject Alternative Name (SAN)** — allows multiple hostnames or other identities to be included within a certificate.

### Symmetric vs Asymmetric Cryptography

| Type           | Key Structure           | Main Uses                                                            |
| -------------- | ----------------------- | -------------------------------------------------------------------- |
| **Symmetric**  | Shared secret key       | Bulk encryption and large amounts of data                            |
| **Asymmetric** | Public/private key pair | Key exchange, authentication, digital signatures and non-repudiation |

**Symmetric cryptography** is generally faster and is suitable for encrypting large amounts of data.

**Asymmetric cryptography** uses a public/private key pair and supports secure key exchange, authentication and digital signatures.

For asymmetric encryption:

**Recipient's public key → encrypt**

**Recipient's private key → decrypt**

For digital signatures:

**Sender's private key → sign**

**Sender's public key → verify**

### Common Cryptographic Algorithms

**Symmetric:**

* AES
* 3DES
* Twofish
* Blowfish

**Asymmetric:**

* RSA
* ECC
* Diffie-Hellman
* ElGamal

AES is widely used for efficient bulk encryption, while RSA, ECC and Diffie-Hellman are examples of asymmetric cryptographic technologies.

### Hashing

Hashing is a **one-way function** that converts data into a fixed-length digest.

Common uses include:

* Data integrity verification
* File integrity monitoring
* Digital signature processes
* Data validation

Unlike encryption, hashing is not designed to be reversed using a decryption key.

### Salting

A **salt** is random data added as an additional input when hashing data such as passwords.

Salting reduces the effectiveness of **rainbow table attacks** by making precomputed hash values less useful to attackers.

### Digital Signatures

Digital signatures use asymmetric cryptography to provide:

* **Authentication** — helps verify the identity of the sender.
* **Integrity** — helps demonstrate that data has not been altered.
* **Non-repudiation** — provides evidence linking the signature to the signer.

### Cryptographic Hardware

* **TPM (Trusted Platform Module)** — hardware used to securely store and manage cryptographic keys and support technologies such as full-disk encryption and secure boot.
* **HSM (Hardware Security Module)** — dedicated hardware for protecting and managing cryptographic keys and performing cryptographic operations.
* **Hardware Root of Trust** — provides a hardware-based foundation for verifying trusted components.
* **KMS (Key Management System)** — provides centralised management and protection of cryptographic keys and other secrets.
* **Secure Enclave** — an isolated environment for securely processing and storing sensitive information.

### Data Protection & Obfuscation

Different techniques can be used depending on the security requirement:

* **Tokenization** — replaces sensitive data with randomly generated tokens while the original data is stored separately.
* **Pseudonymization** — replaces identifying information with artificial identifiers.
* **Anonymization** — removes identifying information so the original subject cannot be identified.
* **Data masking** — hides part of sensitive information, such as displaying only the final digits of a card number.
* **Steganography** — conceals information within another file, such as an image or video.

### Data States

Cryptographic protection can be applied to data in different states:

* **Data at rest** — stored data can be protected using techniques such as full-disk encryption.
* **Data in transit** — network communications can be protected using technologies such as TLS/HTTPS.
* **Data in use** — data being actively processed in memory may also require protection.

### Key Length & Key Management

Increasing cryptographic key length generally increases the amount of work required to brute-force the key.

Key management also involves the secure:

* Generation
* Exchange
* Storage
* Use
* Destruction
* Replacement

of cryptographic keys.

### Cryptographic Use Cases

Different cryptographic solutions are appropriate for different requirements:

* **Confidentiality** — encryption prevents unauthorised parties from viewing sensitive information.
* **Integrity** — hashing and digital signatures can help detect unauthorised modification.
* **Authentication** — MFA and certificate-based authentication can help verify identities.
* **Non-repudiation** — digital signatures can provide evidence of who signed data.
* **Low-power environments** — ECC can provide strong security with smaller key sizes.
* **Low-latency environments** — efficient cryptographic hardware can help reduce processing delays.

### Key Takeaway

Cryptographic solutions must be selected based on the security requirements and environment. Factors such as performance, key strength, compatibility, resource requirements, longevity and key management all need to be considered when implementing cryptography.
