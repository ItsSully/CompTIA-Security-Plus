## 1.3 Change Management

Change management is the process of managing changes to systems, applications and configurations in a controlled way to reduce security risks, outages and unintended consequences.

### Configuration Management

Configuration management ensures that systems are configured consistently and that their current configurations are known and documented.

**Baselining** establishes a standard configuration or starting point that systems can be compared against.

### Change Management vs Change Control

These terms are related but have different purposes:

* **Change Management** — the overall policy and process that defines how changes should be handled within an organisation.
* **Change Control** — the process of evaluating an individual change request and deciding whether it should be implemented.

### Key Change Management Processes

A change should be:

1. **Requested and approved** — the proposed change is reviewed before implementation.
2. **Assigned an owner** — responsibility for the change is clearly defined.
3. **Analysed for impact** — potential effects on systems, security and stakeholders are assessed.
4. **Tested** — the change is validated in a test environment before being deployed.
5. **Implemented** — the approved change is introduced during an appropriate maintenance window.
6. **Supported by a backout plan** — a documented process is available to restore the previous state if the change fails.
7. **Documented** — system configurations, diagrams and relevant documentation are updated.

### Technical Considerations

Changes may affect:

* Firewall and ACL rules
* Application allow/deny lists
* System availability and downtime
* Application or service restarts
* Legacy applications
* Dependencies between systems and services

Understanding dependencies is particularly important because changing one system can have unintended effects on other systems or services.

### Documentation & Version Control

Documentation provides a record of the current operating environment and how systems are configured. Keeping documentation up to date supports security operations, incident response, business continuity and future system changes.

**Version control** tracks changes to software code and system/application configurations. Git-based platforms are commonly used to manage versions and identify changes between different environments.

### Key Takeaway

Change management is important to security because even legitimate system changes can introduce vulnerabilities, weaken existing controls or cause outages. Changes should therefore be controlled, tested, documented and reversible where possible.
